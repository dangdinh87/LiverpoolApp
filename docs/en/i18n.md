# Internationalisation (i18n)

Bilingual interface support for **English (`en`)** and **Vietnamese (`vi`)** powered by `next-intl` v4, with locale-prefixed static prerendering and RSC client-payload trimming.

---

## 1. URL & Routing Strategy (`src/i18n/routing.ts`)

```typescript
export const routing = defineRouting({
  locales: ["en", "vi"],
  defaultLocale: "en",
  localePrefix: "as-needed",
});
```

- **English (`en`, default):** Served at unprefixed paths (`/`, `/news`, `/squad`, `/fixtures`).
- **Vietnamese (`vi`):** Served under `/vi` (`/vi`, `/vi/news`, `/vi/squad`, `/vi/fixtures`).
- **Single source of truth:** Always use `withLocalePrefix()`, `splitLocalePrefix()`, and `LOCALE_PREFIX_PATTERN` from `src/i18n/routing.ts` (or `Link`, `usePathname`, `useRouter` from `src/i18n/navigation.ts`). Never hard-code `"/en"` or `"/vi"` in components, metadata, or route handlers.

---

## 2. Static Prerendering & Request Negotiation

- **Server config (`src/i18n/request.ts`):** Resolves `locale` from the `[locale]` segment (via `setRequestLocale(locale)` in `src/app/[locale]/layout.tsx` and pages) — never from `cookies()` or `headers()` — so both English and Vietnamese pages statically prerender (SSG/ISR).
- **Request proxy (`src/proxy.ts`):** Runs `createIntlMiddleware(routing)` at the edge, honouring the `NEXT_LOCALE` cookie (365-day expiry) and `Accept-Language` header to redirect/rewrite visitors cleanly.
- **Language Switcher (`src/components/layout/LanguageSwitcher.tsx`):** Supports `"dropdown"` (desktop navbar, keyboard-navigable with `ArrowUp`/`ArrowDown`/`Escape`) and `"segmented"` (mobile sheet) variants, writing `NEXT_LOCALE` and navigating to `withLocalePrefix(barePath, targetLocale)`.

---

## 3. RSC Client Payload Optimisation (`pickClientMessages`)

Passing the entire `src/messages/{locale}.json` file (~45–53 KB per locale) into `<NextIntlClientProvider>` would duplicate large server-only namespaces (`Legal`, `History`, `About` prose, `Stats`, `Season`, `Analysis`, `News.digest`, `PlayerDetail` nationalities) into every page's HTML and RSC flight payload.

`src/app/[locale]/layout.tsx` filters messages before hydration:

```tsx
const messages = await getMessages();
const clientMessages = pickClientMessages(messages);
return <NextIntlClientProvider messages={clientMessages}>{children}</NextIntlClientProvider>;
```

- `CLIENT_MESSAGE_NAMESPACES` (`src/components/providers/client-messages.ts`) lists the exact 25 dot-paths consumed by `"use client"` components, cutting serialised client i18n payloads by **~52%**.
- `src/components/providers/__tests__/client-messages.test.ts` walks the full TypeScript client import graph across `src/` and fails `npm test` if any client `useTranslations(...)` namespace or static key is missing.

| File | Scope |

## 5. Adding New Translations

1. Add the key to **both** `src/messages/en.json` and `src/messages/vi.json` with matching `{placeholders}`.
2. In Server Components: `const t = await getTranslations("Namespace");`
3. In Client Components: `const t = useTranslations("Namespace");` — if `"Namespace"` is not already in `CLIENT_MESSAGE_NAMESPACES`, add it in `src/components/providers/client-messages.ts`.
4. Run `npm test` to verify `messages-parity.test.ts` and `client-messages.test.ts`.
