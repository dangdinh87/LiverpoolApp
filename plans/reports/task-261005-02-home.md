## Goal: in 3 seconds on a phone the visitor knows "when/what is the next match, how did we do, what's the news"
1. **IA (mobile order)**: compact hero with next-match card integrated (crests, kickoff in Vietnam time + hydration-safe countdown via `useNowAfterMount`, competition, "match detail" CTA; live state with score/minute and gold pulse) → recent results/form strip → top news (1 lead + list) → standings preview (Liverpool row always visible ±2 neighbours) → squad/stats teaser → news by category. Desktop: 12-col grid (lead news + match card side by side). The "no upcoming match" state is honest (no invented fixture) — keep it.
2. **Hero**: keep stadium photography but small and fast (priority only on the LCP image, `sizes`, ≤200KB), text legible via scrim, SSR renders VISIBLE text (replace framer-motion opacity:0 entrances with CSS `.reveal`).
3. **News section**: strong lead card + compact list; fixed aspect boxes (no CLS), fallback tile when image missing/blocked, source badge + relative time (Vietnam-time helpers in `src/lib/format-match-date.ts`), prefer Vietnamese first. One reusable `NewsCard` for all variants. Defensive rendering: strip HTML entities in titles, replace boilerplate snippets ("appeared first on …") with category label.
4. **Empty/outage states** via `EmptyState` when news/standings/fixtures are unavailable — never a blank band.
5. **Motion**: CSS-only reveals; carousels via CSS scroll-snap (no JS drag lib); hover = border/background only; remove `home-scroll-wrapper` if it adds jank.
6. **Performance**: server components for everything static; client only for countdown/live polling/carousel controls; `defer-render` on below-fold sections; `loading.tsx` skeleton matching layout; no hydration warnings.
7. Data via existing `@/lib/football` and `@/lib/news` helpers; don't change data-layer code.
